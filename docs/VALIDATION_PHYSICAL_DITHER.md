# 原生物理转换验证记录

环境：Linux x64，.NET SDK 10.0.403。材料均为假设配置，使用合成灰阶标靶，未刻录实盘。此记录验证软件计算与接口，不验证43523实盘画质。

## v2.2基线记录（v3之前）

- 完整解决方案Release交叉编译：0警告、0错误。
- DVD自检：新增反射互易性、半球能量预算、物理二值/alpha、中心孔、缓存身份、取消和单像素源图扩展检查；原有编码自检继续通过。
- Python参考原型10项测试通过。
- 原生光学检查点与Python独立计算最大相对差约5.79×10⁻⁷。
- 用独立Python卷积重新计算80微米完整图案的多尺度目标：优化前1.0735944101268255，优化后1.0729222718975986。实际下降0.0006721382292269595，原生记录接受下降量0.0006721382243523461；两者差约4.9×10⁻¹²。下降幅度较小，不能表述为实盘画质显著提升。
- 带透明留白的输入经`solve --physical-profile`生成32扇区；遮罩逐像素吻合物理最近邻采样和环带边界。两个ECC块控制21879个payload字节，其余区域保持原有排除规则。
- 对一个生成的32768字节payload块做完整编码，得到619008个通道电平。
- 使用隔离的HEAD源码构建原版CLI；新功能关闭时，两者生成的65536字节样本完全一致，SHA-256为`2dba2e3e94b2436a78a97419f08696b951d3a3beb7728819c5d51b19ed93df6d`。
- Windows架构测试已增加物理命令路由和schema 3配置往返、旧工程清除物理模式、非法材料快照不修改当前状态的用例；测试项目交叉编译通过。

独立对照可用`tools/PhysicalDither/check_native_reference.py`复现，传入同一输入和设置下、优化轮数分别为0及4的报告。脚本现已更新到v3目标，验证源文件哈希、光学检查点、16×16点数守恒，并在相同半色调观察足迹与有效遮罩下重算整体损失。旧数值仅是v2.2历史记录，不能与v3损失直接比较。

## v3灰阶与抖动修正

此前全局反演在合成图上约26%的位置越界；80微米网格上的20微米观察尺度近似逐点评分，加上自由翻点，会偏向二值色块。这些结果不能用于宣称实盘画质改善。

v3默认保留感知灰阶，关闭未标定反演补偿，以密度误差扩散初始化，仅在16×16区域内交换抖动点。反射评分使用局部混合目标和对比归一化；评价足迹至少覆盖1.2个单元。

已通过原生7级灰阶（32/64/96/128/160/192/224）密度误差小于0.5个百分点、严格单调；无光学对比时仍保留中灰抖动；线性密度须显式启用；补偿不超过配置上限；带圆环遮罩、跨128格计算块的梯度图优化后，每个16×16块白点数完全不变且目标函数下降。完整DVD自检通过。

完整1451×1451、80微米、同一合成灰阶图的v3验证：源图平均密度0.68366077，输出0.68366858；实际密度裁剪比例为0。原中灰片区在v2.2中仅5.505%白点，v3恢复为50.610%（源图约50.588%）。该片区不是用户原始照片。

独立Python卷积重算v3多尺度损失：991.40118196 → 716.75646916，下降274.64471280；原生接受下降量274.64470408，差约8.7×10⁻⁶。光学检查点相对差仍为5.79×10⁻⁷，所有16×16区域的白点数变化均为0。新的目标函数与v2.2不同，不能把其数值下降当成实盘提升比例。

本次80微米、4轮计算21.12秒，峰值RSS约122 MiB（含并发基线转换影响）；无优化基线2.67秒。v3 20微米、4轮尚未测量。

v3.1另外修正GUI缩略图：生成面积平均的`density.png`，遮罩边界使用覆盖alpha，并启用高质量显示缩放。完整`binary.png`与`masked.png`继续用于检查及导出，转换算法和v3灰阶数值不变；缓存模型版本更新，避免读取旧结果缺少的预览文件。

## 物理模式界面流程回归

修正了物理预览失效时一并清空源图路径、导致刷新按钮禁用的问题。设计页现在只清空结果并保留输入，显示计算进度与配置错误。标定预览接入与导出/刻录相同的准备入口，并通过显式`PhysicalBinary`严格读取预抖动图案；物理模式显示“物理抖动”，不再显示旁路旧影调的0%。
